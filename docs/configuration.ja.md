# 設定

depup 自身の設定ファイルは 2 つあります。自分用のデフォルトを書くグローバル設定ファイルと、モノレポで処理するディレクトリを並べる `.depup` です。このほか、プロジェクトの pnpm・Bun・mise の設定に書かれた最小公開期間も適用されます。`--age` やグローバル設定との優先順位は「[適用される age の優先順位](usage.ja.md#適用される-age-の優先順位)」を参照してください。

## グローバル設定ファイル

depup は初回実行時に、デフォルトの設定を説明コメント付きで書いた `~/.config/depup/config.toml` を作成します。既存のファイルは上書きしません。値を編集すると、すべてのプロジェクトに共通するデフォルトを変えられます。1 回の実行だけ変えたいときは、コマンドラインのオプションを使います。オプションは設定ファイルの値より優先されます（[更新候補の絞り込み](usage.ja.md#更新候補の絞り込み)の各節にある優先順位を参照）。

パスはどの OS でも、ホームディレクトリの下の `.config/depup/config.toml` です。Windows なら `%USERPROFILE%\.config\depup\config.toml` になります。

次の例は生成される雛形の内容です（実際のファイルのコメントは英語です）。

```toml
# depup のグローバル設定
# https://github.com/owayo/depup
#
# このファイルは初回実行時に自動生成されます。
# 下の値を編集すると、depup の組み込みデフォルトを上書きできます。

# depup を実行するたびに適用する age フィルターのデフォルト。
# --age と同じ書式: Nd（日）、Nw（週）、Nm（か月）。
# 実行ごとに --age <DURATION> で上書き、または --no-age で無効化できます。
age = "1w"

# 更新候補を OSV.dev の脆弱性データベースで照会し、
# 既知の脆弱性があるバージョンを候補から外します（デフォルトで有効）。
# ネットワーク接続が必要です。API エラー時は元の候補を採用します。
# 実行ごとに --osv / --no-osv で上書きできます。
osv = true

# 許容するバージョン変更の上限。
# "patch"（patch のみ）、"minor"（patch と minor）、
# "major"（デフォルト。すべて許可）のいずれかを指定します。
# 実行ごとに --max-change <LEVEL> で上書きできます。
# max_change = "minor"

# 確認済みの GitHub の身元で公開された版を、公開期間の制限から除外します。
# 自己申告の repository URL は根拠にしません。詳細は docs/configuration.ja.md を参照してください。
# [age_exempt]
# github = ["example-dev"]
```

ファイルにないキーには、組み込みデフォルト（`age = "1w"`、`osv = true`、`max_change` の制限なし）が使われます。ファイルを作成・解析できない場合は、警告を表示して組み込みデフォルトを使います。値が不正なキー（`age = "abc"` など）は、警告を表示したうえで、そのキーだけを組み込みデフォルトに戻します。

## 確認済みの公開者による age の例外

通常の待機期間を維持し、指定した GitHub アカウントだけを例外にするには、グローバル設定に次のように書きます。

```toml
age = "2w"

[age_exempt]
github = ["example-dev", "example-org"]
```

既定では例外は空です。ログイン名を完全一致で照合し、大文字・小文字は区別しません。不正な名前は警告して除外します。`age_exempt` テーブルの形式やキーが不正な場合も、例外だけを無効にし、他の設定は維持します。

対応する根拠は、crates.io の版ごとの公開者情報（GitHub ログイン名の一致が確認された `published_by`、または GitHub Trusted Publishing）と、Go・Swift の GitHub 取得元です。パッケージ名、別レジストリの同名アカウント、現在のクレート所有者一覧、自己申告の repository URL からは GitHub の身元を判断しません。他のレジストリには通常の age 制限を適用し、対象に含まれる場合は通知します。

Swift のタグには現状公開日の情報がなく、age フィルターはもともと実質適用されません。

例外が外すのは公開期間の制限だけです。ピン留め、バージョン範囲、プレリリースの扱い、`--max-change`、OSV チェックは引き続き適用します。プロジェクトに明示された `minimumReleaseAge` は優先され、グローバルの例外を無効にします。Git 依存は従来から公開期間の制限対象外です。

候補選択、Tauri の同期、`--install` 後の Rust lockfile 監査で同じ設定を使い、推移依存のクレートにも適用します。例外で更新する場合はテキスト出力に根拠を表示し、JSON 出力には `identity` と `evidence` を持つ `age_exemption` オブジェクトを追加します。

## `.depup` 設定ファイル

複数のサブディレクトリを持つモノレポでは、プロジェクトのルートに `.depup` ファイルを作成し、追加で処理するディレクトリを列挙できます。

```text
# .depup
gui       # フロントエンドアプリ
api       # バックエンド API
shared    # 共有ライブラリ
```

ルートディレクトリで `depup` を実行すると、ルート自体と列挙したすべてのディレクトリの依存関係をまとめて更新します。バージョン情報はキャッシュされるため、同じパッケージを取得するのは 1 回だけです。

`--install` を指定した場合は、更新したマニフェストを含む対象ディレクトリのうち最も深いもので、パッケージマネージャーの install を実行します。入れ子になったアプリの install は、リポジトリのルートではなく各アプリのディレクトリで行われます（[パッケージマネージャーの実行](usage.ja.md#パッケージマネージャーの実行--install)）。

`.depup` の書式は次のとおりです。

- `#` 以降はコメント（行頭・行末のどちらでも可）
- 空行は無視
- パスは `.depup` ファイルの配置ディレクトリからの相対パス
- 絶対パス、`..` を含むパス、`.depup` の配置ディレクトリの外を指すシンボリックリンクが 1 行でもあると、警告を出して `.depup` 全体を無視（`.depup` がない場合と同じく、ルートと自動検出されるワークスペースを処理）
- 存在しないディレクトリは警告して無視
