# JSON マニフェスト更新の測定記録

[English](README.md)

2026-10-29 に測定しました。JSON 直下のプロパティを一時 Vec に集めず逐次処理し、エスケープの展開が不要な文字列は入力から借用する変更です。エスケープ付き文字列の検証・展開は引き続き serde_json が行います。Node・Bun catalogs・Composer が共通の走査処理を使い、公開パーサ API と書き換え規則は保持しています。

## 条件

- Windows x86_64、AMD Ryzen 7 5700X（8 コア・16 論理プロセッサ）。
- rustc 1.99.1（`58cf8f9c3`、LLVM 23.1.1）、MSVC ターゲット。前後とも依存更新コミット `8b07b212e5e3b61d2af2b7af577ef897524e6674` の `Cargo.lock`・`mise.toml` を使用。このコミットの実装を変更前としました。
- `mise exec -- cargo build --release --locked --example manifest_update_bench` でビルド。release 設定はリポジトリの LTO・codegen-units=1・strip を使用。
- 実行コマンドは `manifest_update_bench 1000 7`。各プロセスで各ケースを 100 回ウォームアップし、1 サンプルにつき 1,000 回更新。各実装を 2 プロセスで測り、計 14 サンプルを比較しました。順序は before-a → after-a → after-b → before-b。測定中はビルドやテストを動かしていません。
- 入力生成は計測外です。最後の依存を `^1.0.0` から `^2.3.4` へ更新し、`overrides` 内の同名キーは保持します。毎ケースで出力 JSON を検証し、エスケープ付きケースではキーの綴りと CRLF の個数も確認します。
- 確保回数・バイト数はウォームアップ後の別の 1 更新で集計。時間の計測中は集計を止め、両実装で同じ計測用アロケータを使います。バイト数は再確保を含む要求量であり、ピークメモリや常駐メモリではありません。
- ネットワーク・レジストリ応答の解析・ファイル書き込み・CLI 全体の時間は含みません。

## 結果

時間は 14 サンプルの中央値、単位は更新 1 回の µs です。丸め前の中央値と最小・最大値は [comparison.csv](comparison.csv) にあります。

| ケース | 変更前 µs | 変更後 µs | 時間短縮率 | 確保要求回数 | 確保要求バイト数 |
|---|---:|---:|---:|---:|---:|
| Node 依存 1 件 | 2.952 | 2.542 | 13.90% | 36 → 21 | 2,236 → 1,650 |
| Node 依存 100 件 | 25.610 | 21.331 | 16.71% | 140 → 21 | 19,870 → 11,748 |
| Node 依存 1,000 件 | 228.706 | 194.051 | 15.15% | 1,043 → 21 | 169,078 → 103,548 |
| Node エスケープ付きキー 100 件・CRLF | 36.688 | 35.862 | 2.25% | 340 → 321 | 24,109 → 17,587 |
| Bun ネストした catalog の依存 100 件 | 41.078 | 37.590 | 8.49% | 149 → 24 | 21,844 → 13,419 |
| Composer 依存 1,000 件 | 120.884 | 94.538 | 21.79% | 1,026 → 13 | 131,166 → 66,992 |

依存 1,000 件での確保要求バイト数は Node で 38.76%、Composer で 48.93% 減りました。エスケープ付きキーの時間分布は前後で重なるため、小さな中央値の差を明確な高速化とは扱いません。確保量は確定的に減っています。測定したケースでは中央値の悪化と確保回数・バイト数の増加はありませんが、別の環境や CLI 全体の速度まで示すものではありません。

生データ: [before-a](before-a.csv)、[after-a](after-a.csv)、[after-b](after-b.csv)、[before-b](before-b.csv)。[preliminary-before.csv](preliminary-before.csv) は初回の探索的な基準値で、最終比較には含めていません。中央値は実装ごとの a・b の `ns_per_update` をケース別にまとめ、14 値の中央 2 値を平均します。短縮率は `(1 - 変更後 / 変更前) * 100` です。

測定した実行ファイルの SHA-256 は英語版に記録しています。
